## 第一章 项目背景 00:40–02:40

### 镜 2｜00:40–01:18｜画面：slides 痛点页（散落文件图标 + 锁图标）

**画面**：左侧 CSV/TXT/JPG/MP4 图标散乱排列，右侧大问号：能用吗？合规吗？

**旁白**：

> 先说为什么做这个项目。企业里的数据往往散落在各个部门：车队的 GPS 轨迹是 CSV 文件，司机日志是文本，现场资料是图片和视频。这些数据格式不统一、质量参差不齐，还混着手机号、身份证号这样的敏感信息，既不敢直接使用，也没法变成可交易的数据产品。

### 镜 3｜01:18–01:56｜画面：slides 三问页

**画面**：三个大卡片依次出现：①数据怎么治理干净？②怎么沉淀为资产/数据集？③怎么合规地变成产品？

**旁白**：

> 本项目就要回答三个问题：第一，多模态数据怎么被自动治理干净；第二，治理后的数据怎么沉淀为数据资产、组装成可复用的数据集；第三，数据集怎么通过合规检验，加工成可以登记挂牌的数据产品。

### 镜 4｜01:56–02:40｜画面：slides 定位页（8GB / 4 容器 / 15 步 / 20 分钟）

**旁白**：

> V0.1 是 MVP 演示版本。一台 8GB 内存的普通电脑，四个 Docker 容器一键启动，十五步演示动线大约二十分钟走完全链路。它不追求生产级规模，但模块边界与真实企业应用一致，未来可以平滑演进到微服务和对象存储。

## 第二章 核心功能 02:40–05:50

### 镜 5｜02:40–02:58｜画面：slides 六模块全景页

**旁白**：

> 平台共六个模块，对应数据流转的六个环节：IAM 认证权限、PROC 文件处理、GOV 资产治理、DS 数据集、PROD 数据产品，以及 SCR 可视化大屏。

### 镜 6｜02:58–03:27｜画面：slides IAM 页；可穿插 2 秒用户管理 403 界面

**旁白**：

> 第一是 IAM。它提供 JWT 登录认证、基于角色的功能权限 RBAC，以及基于密级和部门的属性权限 ABAC。比如只读账号访问用户管理会被 403 拦截；所有接口操作都会写入审计日志，形成等保要求的操作闭环。

### 镜 7｜03:27–04:09｜画面：slides 五阶段流水线图

**旁白**：

> 第二是 PROC 文件处理服务。文件上传后进入五阶段流水线：接收校验、清洗、标准化、脱敏、登记。以五万行车队 GPS 数据为例，系统自动检出约百分之二的缺失、百分之一的完全重复、五十个漂移点和二十条时间乱序，敏感列自动掩码，全程不到六十秒。

### 镜 8｜04:09–04:33｜画面：slides 多模态三宫格（文本掩码 / EXIF 剥离 / 视频缩略图）

**旁白**：

> 文本、图片、视频同样自动处理：文本中的手机号、邮箱、身份证被掩码；图片剥离带 GPS 的 EXIF 信息；视频用 ffmpeg 抽取缩略图并清除元数据。

### 镜 9｜04:33–05:01｜画面：slides GOV 页（资产目录→详情→血缘→热力图缩略）

**旁白**：

> 第三是 GOV 资产治理。处理完成的文件自动登记为数据资产，记录字段、密级和血缘关系；血缘图展示从原始文件到成品的完整链路，热力图反映各业务域每天的资产使用热度。

### 镜 10｜05:01–05:32｜画面：slides DS 页（三维雷达图示意 + v1/v2 对比）

**旁白**：

> 第四是 DS 数据集。按模态、业务域、质量分筛选资产，一键生成不可变的版本快照，系统给出完整性、一致性、准确性三维质检报告，综合分低于零点八五不能进入产品环节，版本之间还可以对比增删和指标差异。

### 镜 11｜05:32–05:50｜画面：slides PROD+SCR 页

**旁白**：

> 第五是 PROD，本项目的核心：三种产品形态、内置状态机和四道合规规则，通过后生成 PDF 说明书与登记凭证；最后由 SCR 大屏实时呈现全局指标。

## 第三章 技术架构 05:50–09:20

### 镜 12｜05:50–06:23｜画面：slides 四容器架构图

**旁白**：

> 架构上采用四容器编排。门户 nginx 是唯一入口，监听 8090 端口，负责托管 Vue 前端并分发 API：处理类请求转给 Python FastAPI 服务，其他请求转给 Java Spring Boot 服务。两个后端服务共用一个 PostgreSQL 16 数据库和一个共享文件卷。

### 镜 13｜06:23–07:04｜画面：slides Java 模块分层图

**旁白**：

> Java 后端是 Maven 多模块结构：platform-common 放统一响应、JWT、切面、审计这些公共能力；iam、governance、dataset、product 四个业务模块各自包含实体、Mapper、Service、Controller；platform-boot 是启动入口，还包含大屏聚合与开放 API。模块之间禁止直查对方的表，只能通过 api 子包提供的接口取数。

### 镜 14｜07:04–07:33｜画面：slides 五 schema 图（iam/proc/gov/ds/prod）

**旁白**：

> 数据库设计为五个 schema：iam、proc、gov、ds、prod，与业务域一一对应。所有表统一带软删除标志和审计字段，快照、质检报告这类半结构化数据用 jsonb 列存储，初始化由七个 SQL 文件按序执行并写入种子数据。

### 镜 15｜07:33–08:09｜画面：slides 安全三道关 + 内部令牌

**旁白**：

> 安全链路上有三道关。第一关 JWT 过滤器解析令牌、还原用户上下文；第二关 RBAC 切面对带注解的接口做权限点校验，管理员直通；第三关 ABAC 引擎在业务代码里比对主体密级、部门与资源属性。跨服务的内部回调则使用独立的 Service Token，不对门户暴露。

### 镜 16｜08:09–08:42｜画面：slides 审计 Filter 流程图 + PG 队列 worker 图

**旁白**：

> 审计由一个 Servlet Filter 自动覆盖所有 /api 请求，异步落库，业务代码零侵入。Python 侧流水线用 PostgreSQL 队列表驱动：两个 worker 线程轮询抢任务、用行锁防止重复领取；服务重启后，卡住的任务会自动续跑，保证任务不丢。

### 镜 17｜08:42–09:20｜画面：slides 端到端数据流图（文件→五阶段→资产→数据集版本→产品→挂牌→大屏）

**旁白**：

> 前端使用 Vue 3、Vite、Element Plus、Pinia 和 ECharts，按页面懒加载，大屏十秒轮询一次。端到端的数据流向是：文件进入，经过五个阶段治理成为资产，被快照进数据集版本，再由产品引擎打包或签发 API，通过合规校验后挂牌——全过程的状态在大屏和审计日志里都看得见。

## 第四章 关键代码实现解析 09:20–13:20

### 镜 18｜09:20–09:48｜画面：IDEA 打开 Result.java / ErrorCode.java / GlobalExceptionHandler.java

**画面**：依次打开三个文件各停留 8 秒；字体放大到 18pt。

**旁白**：

> 先看公共约定。所有接口返回统一结构：code、message、data，code 为零表示成功，HTTP 状态码恒为 200。错误码是六位数字，前三位标识模块，比如 600 开头代表产品模块。全局异常处理器负责把业务异常翻译成统一响应。

### 镜 19｜09:48–10:32｜画面：IDEA 打开 RbacAspect.java（重点）

**画面**：高亮 `@Before("@annotation(p)")` → `UserContext.get()` → admin 放行 → 权限集合比对 → 抛 PERM_DENIED。

**旁白**：

> 权限控制的核心是 RbacAspect 这个切面。它用 @Before 切所有标注了 @RequirePerm 的方法：先从 UserContext 取当前用户，未登录抛出 401；admin 角色直接放行；否则遍历接口要求的权限点，只要用户权限集合里缺任何一个，就抛出权限拒绝。业务方法本身只需要加一个注解，比如产品导出标注 prod:product:export。

### 镜 20｜10:32–10:58｜画面：IDEA 打开 AbacEngine.java 与 IamApi#checkAccess 调用处

**旁白**：

> RBAC 解决能不能进入功能，ABAC 解决能不能看这份数据。资产查询时，用户密级、部门、角色组成主体属性，资产密级、归属部门组成资源属性，交给 checkAccess 判定，不满足条件的资产在数据库查询阶段就被过滤掉。

### 镜 21｜10:58–12:03｜画面：IDEA 打开 ComplianceEngine.java（本章重点，停留最久）

**画面**：依次高亮：批次号生成 → 四条 `rule*` 调用 → 逐条 insert → allPassed 决定 PASSED/BLOCKED；再滚到四个 rule 方法。

**旁白**：

> 最能体现业务价值的是合规引擎 ComplianceEngine。run 方法先把产品置为校验中，生成一个批次号，然后依次执行四条规则：R1 密级合规，原料最大密级不能高于产品密级；R2 敏感列脱敏，通过 GOV 模块接口查出全部敏感列，逐一确认配置了脱敏策略；R3 质量达标，读取数据集版本的综合分，阈值默认零点八五；R4 说明书完整，校验四个必填要素。每条结果都带着人能读懂的原因文案落库，四条全绿才是 PASSED，否则就是 BLOCKED。

### 镜 22｜12:03–12:35｜画面：IDEA 打开 ProductService.java 的 configure / register

**画面**：高亮 `assertStatus(product, "DRAFT")`、`REG-` + today + randomDigits(6)。

**旁白**：

> 产品状态机在 ProductService 中用 assertStatus 强约束：配置只能从草稿态推进，登记只允许合规通过状态，登记时生成 REG 加日期加六位随机数的凭证号，任何非法状态跳转直接抛出 600003 错误。显式状态机能防止误操作导致的数据混乱。

### 镜 23｜12:35–13:20｜画面：VS Code 打开 processing-service/app/worker.py 与 pipeline/__init__.py

**画面**：高亮 STAGES 列表 → worker 顺序执行循环 → 失败重试计数 → callbacks.py 的 Service Token 回调。

**旁白**：

> Python 侧的 worker 同样值得看。五个阶段名定义为常量列表：接收校验、清洗、标准化、脱敏、登记。worker 抢到任务后从当前阶段开始顺序执行，每个阶段返回的指标写入 meta；任何阶段失败都会记录错误并按重试次数重新入队。处理完成后，它带着 Service Token 回调 Java 的内部接口，幂等登记资产、字段元数据和血缘边——同一份文件重复回调不会产生重复资产。
